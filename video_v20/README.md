## 当前用途

把用户提供的两段 MP4 在电脑上转换为 FPGA 可连续读取的 `.FPV` 文件，再从 TF 卡播放画面和伴音。
这是与 V19 分开的实验工程；V19 的图片、音乐、素材清单功能仍保存在原工程及板上 Flash。
V20 不直接解码 H.264/AAC，也不把原始 MP4 直接复制到卡上播放。

## 第一次试用

1. 开发板断电，取下 TF 卡，用 USB 读卡器接电脑。
2. 将本目录 `TF_CARD` 下 **VIDEO01.FPV、VIDEO02.FPV** 复制到卡的根目录。总大小约 75 MiB。保留 V19 原有的 BMP、FPA、PLAYLST.BIN 等文件。
3. 安全弹出读卡器，把卡插回开发板的 U51 卡槽，再上电。HDMI 使用此前 V19 能正常工作的接口。
4. SW2 拨上可播放声音；SW3、SW4 先拨下。默认音量 10%。
5. BitWriter 选择本目录 `competition_video_v20.bit`，使用 **JTAG / SRAM Download**。也可运行 `DOWNLOAD_SRAM.ps1`。
6. 新画面顶部应显示 **FPGA V20 VID 1**。第一段是 Magical Flavor，第二段是三日月 Step。
7. 上板观察画面是否连续运动、原片伴音是否连续、切换两段是否正常。编译成功不代表这三项已通过；实际上板结果见 `BUILD_STATUS.json`，未确认时记为待确认。

**不要选择 Flash Program / Program SPI。** 断电重启后恢复 V19 是本实验的预期行为。

## 操作

| 控件 | 正常播放模式（SW4 下） | 设置模式（SW4 上） |
|---|---|---|
| KEY1 | 下一段视频（两段互换，从头播放） | 当前参数增加 |
| KEY2 | 上一段视频（两段互换，从头播放） | 当前参数减少 |
| KEY3 | 音量减 5%，最低 0% | 轮换音量 / 亮度 / 对比度 |
| KEY4 | 音量加 5%，最高 100%；出错时优先重试当前视频 | 出错时重试 |
| SW1 | 上：一段播完自动切下一段，循环；下：播完保持末帧 | 同左 |
| SW2 | 上：声音开启；下：静音，视频继续 | 同左 |
| SW3 | 上：显示音频波形；下：隐藏 | 同左 |
| SW4 | 下：正常模式；上：打开参数设置 | 拨下退出 |

按键及开关沿用 V19 的同步、20 ms 消抖。音量、亮度、对比度在切换视频时保留，掉电后恢复默认值。
本版没有播放暂停、进度拖动和 MP4 文件浏览功能。手动切视频会重新打开文件，切换时有加载间隔。

## 画质及声音参数

| 项目 | V20 实验规格 |
|---|---|
| 原片 1 | Magical Flavor，1280×720，30 fps，约 2 分 1 秒 |
| 原片 2 | 三日月 Step，1920×1080，30 fps，约 3 分 9 秒 |
| 存储画面 | 160×90，15 fps，每帧独立 256 色调色板 |
| 显示 | 640×480 HDMI 时序中居中显示 640×360；4 倍最近邻放大，保持 16:9 |
| 伴音 | 原片音轨转为 24 kHz 单声道 μ-law；FPGA 还原并插值到 48 kHz，左右声道相同 |
| 数据流 | 每帧 16,896 字节；每秒 253,440 字节，约 0.25 MB/s |
| 文件 1 | VIDEO01.FPV，30,717,440 字节，1818 帧，121.2 秒 |
| 文件 2 | VIDEO02.FPV，47,968,256 字节，2839 帧，约 189.27 秒 |

这是低分辨率可行性版本，像素块、色阶和 15 fps 的运动感会明显区别于原片。声音也不是原 AAC 立体声无损输出。
输出帧刷新与视频内容帧率不同：显示器持续扫描约 59.52 Hz，视频按伴音进度更新约 15 次/秒。

## 原理

电脑 FFmpeg 解码 MP4 → 缩小画面 / 降帧 / 生成调色板并转换伴音 → FPV 文件 → TF 卡 FAT16/FAT32 文件读取 → 帧头检查与 CRC32 → 后帧缓冲和音频暂存 → 垂直消隐切换显示缓冲 → HDMI 画面与音频。

- 两个独立画面缓冲，正在显示的帧不被下一帧的写入覆盖。
- 每帧的像素、调色板和伴音共用 CRC 校验；校验通过后才提交伴音和画面。
- 已消耗的音频采样数决定下一帧何时显示，避免因显示刷新频率的小偏差持续积累音画时间误差。
- 伴音使用片内 FIFO；视频版不经过 V19 的 SDRAM 音频读写通路。
- 字幕、参数面板、音频波形、数字音量和 HDMI 打包沿用已用过的模块。
- 如果读卡速度跟不上，可能暂时停帧或伴音断续；此时 LED4 会记录音频欠载。该指标仍需实际 TF 卡验证。

## 指示灯与报错

| 指示 | 含义 |
|---|---|
| LED1 | 首帧已显示 |
| LED2 | 首帧正在加载 |
| LED3 | 自动循环开启（SW1） |
| LED4 | 读取/格式错误，或音频缓冲欠载、溢出、HDMI 音频队列异常；欠载标志会保持到重新加载 |
| VIDEO FILE MISSING | 根目录找不到指定的 VIDEO01.FPV 或 VIDEO02.FPV |
| VIDEO FORMAT ERROR | 文件头或帧编号不符合本版格式 |
| VIDEO CRC ERROR | 文件内容校验不一致 |
| SD READ TIMEOUT | 读取持续无进展 |
| VIDEO FILE SHORT | 文件提前结束 |
| BUFFER OVERFLOW | 缓冲溢出 |

发生错误时保留最后可用画面并停止伴音；KEY4 重试，KEY1/KEY2 可切另一个文件。若只有 LED4 亮且仍在播放，也请记录是否听到断续声。

## 工程及文件

- TD 工程：`competition_video_v20.al`；顶层 `competition`；器件 EG4S20BG256。
- 下载文件：`competition_video_v20.bit`。
- 构建：`build.ps1` / `build.tcl`；结果见 `build_console.log`、`competition_phy.area`、`competition_pr.timing`。
- 转换：`convert_videos.py`，需要 Python、Pillow、FFmpeg；默认读取 `D:/软件/Download` 下恰好两个 MP4，按文件名排序。
- 转换工具不会覆盖已有 FPV；重新转换请指定新的 `--out` 目录。
- `TF_CARD/VIDEO_INFO.json` 记录原片信息、时长和转换文件 SHA256。预览 PNG 仅供电脑查看，不需要复制到卡。
- `FORMAT.md` 说明二进制布局；`rtl/hdmi_audio`、`rtl/sd_spi` 内保留第三方来源与许可。
